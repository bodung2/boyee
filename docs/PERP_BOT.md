# 코인 선물(perps) 추세 추종 봇

Defi App의 선물은 Hyperliquid(HIP-3) 위에서 돌아가므로, 봇은 Hyperliquid API에 직접 연결한다.

> **지금은 1단계: 백테스트와 모의 운용만.** 실제 주문 기능은 없다. 모의 운용 결과를 확인한 뒤 2단계(테스트넷 → 소액 실주문)를 따로 만든다.

## 정한 조건

| 항목 | 값 | 바꿀 수 있나 |
|---|---|---|
| 운용 금액 | 600달러 | |
| 운용 종료 | 평가 잔고 ≤ **400달러** → 다음 봉에 전부 정리하고 영구 정지 | 더 높게만(.env `PERP_STOP_EQUITY`) |
| 대상 | BTC, ETH, SOL | |
| 레버리지 상한 | 전체 포지션 합계 **10배**, 코인 하나 5배 | 더 낮게만(`PERP_MAX_LEVERAGE`) |
| 한 거래 손실 | 손절에 걸리면 잔고의 **2%** | 더 낮게만(`PERP_RISK_PER_TRADE`) |
| 하루 손실 | 6% 넘으면 그날 새 진입 금지 | |

**10배는 "상한"이지 "늘 쓰는 배율"이 아니다.** 포지션 크기는 "손절에 걸리면 잔고의 2%를 잃는 크기"로 정하고, 그 결과가 상한을 넘을 때만 자른다. 예: 잔고 600달러, 손절 거리 5% → 240달러(0.4배). 손절 거리가 짧아질수록 배율이 커지며, 손절이 청산 가격보다 반드시 먼저 오도록 크기를 줄인다.

## 규칙(4시간 봉, 확정된 봉으로만 판단)

1. 추세 강도 = 1·2·4주 수익률 ÷ 변동성의 평균(대시보드와 같은 방식, 4시간 봉으로 계산).
2. 진입: 추세 강도 > 0.5 이고 200봉 지수이동평균 위 → 롱 / 추세 강도 < −0.5 이고 평균 아래 → 숏.
3. 손절: 진입가 ∓ 2.5×ATR(실주문 단계에서는 진입과 동시에 거래소에 손절 주문을 걸어 PC가 꺼져도 작동).
4. 추적 손절: 진입 뒤 가장 좋았던 종가 ∓ 3×ATR. 추세 강도가 0을 지나 반대로 가면 정리.
5. 주문은 신호가 난 다음 봉 시가에 체결된다고 보고, 수수료 0.045% + 미끄러짐 0.03%, 펀딩비를 반영.

## 실행

```powershell
.venv\Scripts\python.exe -m perp_bot backtest      # 실제 시세(약 2.5년)로 백테스트, 설정별 비교
powershell -ExecutionPolicy Bypass -File scripts\setup_perp_windows.ps1   # 4시간마다 모의 운용 예약
.venv\Scripts\python.exe -m perp_bot status        # 모의 운용 상태(포지션·잔고)
```

모의 운용 상태는 `data\perp\paper_state.json`(git에 올라가지 않음). 진입·정리가 있을 때만 텔레그램으로 알린다.

## 2단계(실주문)로 넘어가기 전 조건

- 모의 운용 4~8주 결과가 백테스트와 크게 다르지 않을 것
- 직접 연결한 지갑(메타마스크 등)에서 Hyperliquid **API 지갑**을 만든다(매매만 가능, 출금 불가). 원래 지갑의 비밀키는 어디에도 넣지 않는다.
- 테스트넷에서 진입·손절 주문·전부 정리·잔고 하한 정지를 먼저 확인
