# 성장 실험실 (네이버 투자 블로그 · 티스토리)

주제를 사람이 정하지 않고, **발행한 글의 반응을 보고 시스템이 스스로 주제와 글 쓰는 방식을 바꿔 가는** 장치입니다.

```
[매일 22:30]  python -m growth_lab daily
  ① 수집      발행용 크롬(로그인 저장)으로 블로그 통계 화면을 열어 글별 조회수를 읽음 + 네이버 검색 API로 검색 순위
              → data/lab/metrics_<블로그>.jsonl (하루 한 줄)
              네이버는 '조회수 순위' 화면이 부르는 요청을 날짜별로 다시 보내 글별 '그날 조회수'를 받고(처음엔 60일치),
              발행일부터 더해 N일째 조회수를 정확히 낸다 → data/lab/daily_invest.json
[일요일엔 이어서] 주간 리뷰
  ② 판정      글 점수 = 'N일째 조회수' ÷ 블로그 글들의 'N일째 조회수' 중간값 (네이버 7일, 티스토리 14일)
              주제 점수 = 시험 글 3편 점수의 중간값 → 시험 중 / 유망(1.5배↑) / 주력 / 보통 / 포화 / 중단(0.5배↓ → 무덤)
              · 블로그 전체 조회가 거의 안 늘면 '채널 점검' — 주제 탓으로 보지 않고 무덤에 넣지 않음
              · 조회수는 적어도 검색 상위 10위에 오른 글이 있으면 '입질'로 보고 무덤에 넣지 않음
  ③ 화풍 실험  지금 화풍 vs 새 화풍을 2주간 하루씩 번갈아 → 판정 나이가 되면 비교 → 20% 이상 나으면 채택
  ④ 진단·리서치(Claude, growth-lab-review 스킬)
              막힌 단계(수요·노출·클릭·읽기) 진단, 통계 화면의 실제 유입 검색어 정리, 상위 글·플랫폼 변화 리서치,
              새 주제 후보 → 네이버 데이터랩으로 검색 수요 확인(거의 안 찾는 주제는 쓰기 전에 거름)
              → 플레이북(data/lab/learned_<블로그>.md) 새 판 + 큰 변경 제안
  ⑤ 보고      텔레그램: 주제 점수, 무덤에 들어간 주제, 실험 상황, 제안("승인 투3" / "거절 티2"로 답장)

[글 쓸 때]  투자(07:00)·티스토리(08:30, 17:00) 글쓰기 프롬프트 끝에 '성장 실험실 안내'가 붙음
  오늘 차례: 시험 계속(새 주제 3편 채우기) / 집중(유망 주제, 실제 유입 검색어로) / 탐색(10편 중 3편꼴) / 기본(원래 방식)
  + 무덤 목록(같거나 비슷한 주제는 파이프라인이 막고 다른 주제로 다시 씀) + 오늘 화풍 + 플레이북
```

## 바뀌지 않는 것 (잠긴 규칙)

- 사실 확인·출처 기준, 이중 팩트체크, 투자 권유 금지, 글쓴이 신원 비노출, 경험 지어내기 금지, 위험한 명령 차단은 그대로입니다.
  실험실 안내는 **주제와 그림 화풍만** 정하고, 스킬 규칙과 부딪히면 스킬을 따릅니다.
- 주간 리뷰의 Claude는 리뷰 폴더(`output/lab/`) 안에만 쓸 수 있습니다. 스킬·코드 파일이 바뀌면 리뷰가 끝날 때 되돌립니다.
- 판정 기준(점수·무덤)은 코드에 고정돼 있어 Claude가 숫자를 보고 바꾸지 못합니다. 글 쓰는 규칙을 크게 바꾸는 건 **제안**으로만 올라오고,
  텔레그램으로 승인한 것만 플레이북의 '확정 규칙'이 됩니다.
- 저장소가 공개라서 실험실 자료(`data/lab/`)는 GitHub에 올라가지 않습니다. `diagnose`도 값 없이 구조만 올립니다.

## 처음 한 번

1. 예약 작업 등록(코드는 다음 예약 작업 때 자동으로 받아 옵니다):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\setup_all_schedules.ps1 -Only GrowthLab
   ```
2. 시험 수집: `.venv\Scripts\python.exe -m growth_lab collect` → `python -m growth_lab status`에서 '조회수 찾은 글' 수를 확인합니다.
   - **0편이면** 통계 화면 구조가 예상과 다른 것입니다. `.venv\Scripts\python.exe -m growth_lab diagnose`를 실행하고(구조만 GitHub에 올림)
     Claude에게 "올렸어"라고 알려 주세요. 수집기를 실제 화면에 맞춰 고칩니다. 스크린샷은 `output\lab\<블로그>\diagnose-날짜\`(PC에만)에 있습니다.
3. (권장) 검색 수요 확인: [네이버 개발자센터](https://developers.naver.com/apps/#/list) → 이웃 추천에 쓰는 애플리케이션 → API 설정 →
   사용 API에 **데이터랩(검색어트렌드)** 추가. 안 하면 수요 확인만 빠지고 나머지는 돕니다.
4. 네이버 검색 API 키(`NAVER_SEARCH_CLIENT_ID/SECRET`)가 `.env`에 있으면 검색 순위도 모읍니다(이웃 추천과 같은 키).

## 매일·매주 할 일

- 없습니다. 일요일 밤 텔레그램 보고를 읽고, 제안이 있으면 `승인 투3` / `거절 투3`(투자), `승인 티2`(티스토리)로 답장합니다.
- 언제든: `python -m growth_lab status`(장부 요약), `python -m growth_lab brief --blog invest`(내일 글쓰기에 들어갈 안내 미리 보기),
  `python -m growth_lab review`(주간 리뷰를 지금 실행).
- 끄기: `.env`에 `LAB_BLOGS=`(빈 값). 한 블로그만: `LAB_BLOGS=invest`. 기준값은 `.env.example`의 `LAB_*`.

## 얼마나 걸리나

- 수집기가 글 조회수를 실제로 읽기 전까지는 새 주제 탐색을 미루고 원래 방식(기본)으로 씁니다. 꼬리표(주제 이름·제목 유형·화풍)는 처음부터 남깁니다.
- 판정은 글이 판정 나이(네이버 7일, 티스토리 14일)에 이르고 수집 기록이 쌓여야 시작됩니다. 수집 시작 뒤 첫 2~3주는 '데이터 부족'이 정상입니다.
- 새 주제 하나를 판단하는 데 네이버 약 2주(시험 글 3편 + 7일), 티스토리 3~4주가 걸립니다.
- 화풍 실험 하나는 2주 번갈아 쓰기 + 판정 나이만큼 기다리기라 한 달쯤 걸립니다.
