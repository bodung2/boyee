# 교육 정책 정보성 글 — 완전 자동 발행 모드

이 스킬은 `education-insight-extraction`의 **자동 발행 버전**이다. 파이프라인(`python -m naver_autopost run`)이 매일 1회 호출하고, 여기서 만든 `post.json`은 **팩트체크 통과 후 사람 검토 없이 네이버에 그대로 발행된다.** 그래서 원본 스킬보다 정확성 기준이 더 엄격하다.

호출 프롬프트가 알려주는 값:
- `OUTPUT_DIR`: 결과 저장 폴더(예: `output/2026-09-27`)
- `HISTORY_FILE`: 발행 이력(`data/published.json`, 제목·URL·주제·날짜 목록)
- `TODAY`: 오늘 날짜(Asia/Seoul)

부재 중 자동 실행이므로 질문하지 말고 스스로 판단해 끝까지 진행한다. 판단 근거는 `post.json`의 `research_log`에 남긴다.

## 0. 최상위 원칙 (원본과 동일 + 자동 발행용 강화)

- **정확한 사실 + 명확한 출처가 모든 원칙보다 우선이다.** 노출 전략(C-Rank/DIA, GEO, 홈피드)은 정확성을 해치지 않는 선에서만 적용한다.
- **불확실하면 쓰지 않는다.** 원본 스킬의 '(확인 필요)' 표기는 자동 발행에서 쓸 수 없다. 1차 출처로 확인되지 않는 수치·날짜·명칭은 문장째 뺀다. 본문에 "확인 필요", "추정", "TBD", "○○" 같은 자리표시자가 남아 있으면 파이프라인이 발행을 막는다.
- **경험 위조는 절대 금지다.** "제가 해봤더니", "우리 반 아이들이" 같은 개인 경험·후기·결과를 지어내지 않는다. ✍️ 경험 블록은 만들지 않는다(채울 사람이 없다). 대신 **"현직 교사 관점의 해석"**은 쓸 수 있다. 예: "학교 현장에서는 이 일정이 학기 운영과 겹쳐 3월 전에 미리 챙겨야 합니다." 검증 가능한 사실과 일반적인 현장 구조만 근거로 삼는다.
- **대상 범위: 교육 정책 글만 쓴다.** 원본의 5개 레인 중 (A)경기교육 정책·이슈, (C)전국 교육부 정책, (E)교육 핵심 동향·인사이트에서만 고른다. (B)교직 실무 꿀팁과 (D)학부모 관심 정보는 정책과 직접 연결될 때만 고른다.
- 민감한 정책 쟁점은 특정 정파·입장을 옹호하거나 비난하지 않고 찬반을 균형 있게 다룬다.
- 실존 인물 사진, 실존 학교명, 학생 개인정보는 넣지 않는다.

## 1. 주제 선정

1. `HISTORY_FILE`을 읽어 최근 발행 제목·주제를 확인한다. Google Drive 도구가 있으면 콘텐츠 마스터 시트(ID `1uGQH525NEZjKnUR-tOshU61tbAv4Ws2-6CXukfAvHO0`, '콘텐츠 마스터' 탭)도 읽어 교차 확인한다. 없으면 로컬 이력만으로 진행한다.
2. WebSearch로 최근 2주 안의 교육부·경기도교육청 보도자료, 정책브리핑, 교육 전문지(한국교육신문, 에듀프레스, 교육언론[창], 베리타스알파) 기사를 훑어 후보 3~5개를 만든다.
3. 흥미·가치 점수(각 1점)를 매긴다. ①검색 유입형(총정리·정책해설) ②시의성 ③교사/학부모 실질 도움 ④구체 수치·일정·근거 ⑤전문성·인사이트. 최고점 1개를 고른다.
4. 이력과 사실상 같은 주제는 제외한다. 같은 정책이라도 새 발표나 새 단계가 있으면 "후속편"으로 쓸 수 있다. 이때 이전 글을 내부 링크로 건다.

## 2. 심층 리서치 (원본 2단계 그대로 — 이 스킬의 품질 핵심)

- 최소 **10개 자료**를 WebFetch로 본문까지 읽는다. 제목·스니펫만 보고 쓰지 않는다. 소스는 다양하게 모은다.
  - 1차 출처: 공식 계획·보도자료 원문, 법령·지침, 통계·연구보고서
  - 2차 해설: 교육 전문지·일간지
  - 관점·현장: 전문가 칼럼, 교원단체 입장, 상반된 견해
- **교차검증:** 날짜·수치·명칭이 자료 간 일치하는지 확인한다. 상충하면 1차 출처를 따른다. 1차 출처로 확정되지 않으면 그 내용은 쓰지 않는다.
- **내용 충실성 합격선.** 못 채우면 쓰지 말고 더 조사한다. 끝내 못 채우면 주제를 바꾼다.
  - (a) 핵심 질문 5개와 근거 있는 답
  - (b) 구체 수치·기준 5개 이상, 각각 [수치+출처+연도]
  - (c) 근거를 조문·날짜 단위로 특정
  - (d) 예외·단서 2개 이상
  - (e) 1차 출처 원문 2개 이상 직접 확인
  - (f) 교원 현장 특수성 1개 이상
- **종합:** 단순 요약이 아니라 "왜 중요한가, 무엇이 어떻게 바뀌나, 배경, 상반 관점, 현장 시사점"을 엮은 해석을 만든다.

## 3. 작성 규칙 (원본 3단계 요약 — 자동 발행용 조정 포함)

문체와 구조:
- 자연스러운 1인칭 교사 톤을 쓴다. 예: "저는 이 부분부터 봐요." 단, 경험은 지어내지 않는다.
- **맨 앞:** 3줄 핵심 요약을 `<ol><li>…</li></ol>` 3항목으로 쓴다. 각 문장은 "~입니다"로 단정하고 핵심 수치를 1개 이상 넣는다. 그다음 도입 공감 2~3문장과 이모지 1개. 첫 3문장 안에 끝까지 읽어야 할 이유를 드러낸다.
- **본문:** 1~5 넘버링 챕터. 1번은 전체 프레임을 잡는 '🧭 큰 그림' 챕터다. 소제목은 검색어형 질문으로 쓰고, 첫 문장은 결론·정의문으로 쓴다. 모든 수치는 수치·출처·연도를 한 문장 안에 쓴다. 출처는 대괄호가 아니라 자연스러운 괄호로 쓴다(예: "…82%가 부정적이었습니다(교총 설문, 2025)")(본문 인라인 출처 필수).
- 💡 '놓치면 손해' 포인트 2~3개, 예외·단서, 🔗 조합·활용법을 넣는다. (E)형이면 '배경→핵심→쟁점/관점→시사점' 흐름으로 쓰고, 마무리 직전에 🎓 장학사 시험 포인트 3~5불릿을 넣는다.
- 비교 기준이 3개 이상이면 표로 만든다. 키워드가 2개 이상인 챕터는 '▸ 키워드 | 핵심 결론' 하위 소제목으로 나눈다.
- 제목류의 두 부분 구분자는 '|'를 쓴다. 본문 문장 속 대시는 그대로 둔다.
- **마무리:** 한 줄 요약(`<div data-block="oneline">`) + 다음 글 예고(`<p>`).
- **🔗 함께 보면 좋은 글 2~3개:** `HISTORY_FILE`(및 시트)의 **URL이 있는 발행 글**만 쓴다. 각 항목은 `「제목」 — 관련 이유` 다음 줄에 raw URL을 그대로 노출한다(`<a>` 태그로 감싸지 않는다). URL이 있는 관련 글이 없으면 이 섹션을 통째로 뺀다. 자리표시자를 남기지 않는다.
- **출처:** 끝에 2~3줄 압축형으로 쓰고, 공식 원문 1~2개를 포함한다.

### 블로그 디자인 표시 (필수 — SR 기존 글 서식으로 자동 변환된다)
파이프라인이 아래 표시를 SR의 기존 글과 같은 디자인으로 바꿔 넣는다. 표시를 정확히 지킨다.
- 맨 앞 `<ol><li>…</li></ol>` 3항목 → 회색 1칸 표 안 "⚡ 3줄 핵심 요약" + 글머리표 3개
- `<h2>` → 챕터 제목(세로선 인용구, 19pt 굵게). 챕터 제목은 `<h2>` 한 줄로만 쓴다.
- `<h3>` → 굵은 소제목 줄, `<p>` → 본문 16pt 줄간격 180%
- `<table>` → 가운데 정렬 표(첫 행 머리글 굵게 + 연회색). 첫 행을 반드시 머리글(`<th>`)로 쓴다.
- 한 줄 요약 → `<div data-block="oneline"><p>한 줄 결론 문장</p></div>` (구분선 + 포스트잇 상자). "[한 줄 요약]" 머리말은 쓰지 않는다(자동으로 붙는다).
- 다음 글 예고 문장은 한 줄 요약 `div` 바로 뒤 `<p>`로 쓴다.
- 함께 보면 좋은 글 → `<div data-block="related"><p>「제목」 — 관련 이유</p><p>https://blog.naver.com/…</p> …</div>` (구분선 + "🔗 함께 보면 좋은 글" 머리말 + 링크 카드가 자동으로 붙는다). 머리말은 직접 쓰지 않는다. URL이 있는 글이 없으면 이 `div`를 통째로 뺀다.
- 그 밖의 `<div>`·`<blockquote>`·색·크기 지정은 쓰지 않는다.

**만들지 않는 것** (원본 스킬에는 있지만 자동 발행에서는 뺀다):
- ✍️ 경험 블록과 유도 질문
- 발행 전 확인 체크리스트
- 나노바나나 프롬프트 섹션과 일러스트 자리
- "※ 자동 생성 초안입니다" 안내문
- 출처 줄 선택 안내 문구
- 실제 사진 삽입 안내

### HTML 서식 (SR 스타일: 흰 종이에 검은 글씨)

- `body_html`은 본문 조각만 담는다(`<html>`/`<head>`/`<style>` 없이). 사용할 태그: `<h2>`(챕터 제목), `<h3>`(▸ 하위 소제목), `<p>`, `<ol>`(맨 앞 3줄 요약만), `<ul><li>`, `<table border="1">`(비교 데이터만, 첫 행 `<th>`), `<br>`, 강조는 `<strong>`(챕터당 1개 이내), 디자인 표시용 `<div data-block="oneline|related">`.
- 글자색 지정, 컬러 박스, CSS 클래스, 인라인 style은 쓰지 않는다. 네이버 에디터에 붙여넣을 때 깨진다.
- **이미지 자리:** 요약 카드가 들어갈 곳에 `<p>[[IMAGE:card]]</p>`를 **정확히 한 번** 넣는다. 보통 1번 챕터 뒤에 둔다. 대표 썸네일은 파이프라인이 글 맨 앞에 자동으로 넣으므로 표시하지 않는다.
- 제목(`title`)은 본문에 다시 쓰지 않는다. 네이버 제목 칸에 따로 들어간다.

## 4. 결과 저장 — `OUTPUT_DIR/post.json`

Write 도구로 UTF-8 JSON 하나를 저장한다. 이미지(PNG)는 파이프라인이 `thumbnail`·`card` 필드로 직접 그리므로 **직접 만들지 않는다.**

```json
{
  "date": "2026-09-27",
  "lane": "C",
  "topic": "핵심 주제 한 줄",
  "title": "최종 발행 제목 (| 구분자, 40자 이내 권장)",
  "title_candidates": ["총정리형", "질문형", "결과형"],
  "homefeed_titles": ["통념 반전", "손해 회피", "숫자·구체"],
  "thumbnail": {"chip": "교육 정책", "main": "메인 12자 이내", "sub": "보조 20자 이내", "highlight": "메인 속 포인트색 단어(메인에 실제로 있는 단어)"},
  "card": {"chip": "교육 정책", "title": "카드 제목", "bullets": ["요점 4~5개, 각 40자 이내"], "footer": "출처: 교육부 보도자료(2026.9.20) 외"},
  "image_alts": {"thumbnail": "키워드형 대표 이미지 설명", "card": "키워드형 요약 카드 설명"},
  "image_names": {"thumbnail": "키워드_썸네일_2026", "card": "키워드_요약카드_2026"},
  "body_html": "<p>⚡ 3줄 요약 ...</p> ... <p>[[IMAGE:card]]</p> ...",
  "tags": ["교육정책", "교육부", "... 8~10개, # 없이"],
  "sources": [{"title": "자료 제목", "publisher": "매체/기관", "url": "https://...", "date": "2026-09-20", "primary": true}],
  "claims": [{"text": "본문에 쓴 수치·날짜·명칭 문장 그대로", "source_url": "https://...", "quote": "원문에서 그 사실을 보여주는 발췌 1~2문장"}],
  "research_log": {"sources_read": 12, "lane_score": "C 레인, 5점 중 5점: ...", "key_questions": ["..."], "insight": "핵심 인사이트 한 줄", "why_this_topic": "선정 이유"}
}
```

`claims`는 팩트체커가 원문과 대조하는 목록이다. **본문에 등장하는 모든 수치·날짜·기관명·제도명 사실을 빠짐없이** 넣는다(보통 8~20개). `quote`는 원문에서 실제로 복사한 문장이어야 한다. 요약하거나 지어내면 팩트체크에서 탈락한다.

저장 후 JSON이 올바른지 스스로 확인한다(`python -c "import json;json.load(open('...',encoding='utf-8'))"`). 마지막 응답은 "주제 / 레인 / 자료 수 / 제목" 한 줄로 끝낸다.
