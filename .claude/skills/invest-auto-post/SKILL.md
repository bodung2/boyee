# 숫자로 까 보는 돈·생활 이야기 — 네이버 투자 블로그 자동 발행 글

파이프라인(`python -m naver_autopost run --profile invest`)이 매일 1회 호출한다. 여기서 만든 `post.json`은 아래를 거쳐 **사람 검토 없이 네이버 블로그에 공개 발행된다.**

1. 구조 검증
2. 본문 일러스트 생성(ChatGPT 이미지)
3. Claude 팩트체크(`invest-auto-factcheck`, 그림 검수 포함)
4. ChatGPT(Codex) 교차 팩트체크
5. 썸네일·요약 카드·인포그래픽 → 네이버 서식 → 발행

호출 프롬프트가 알려주는 값:
- `TODAY`: 오늘 날짜(Asia/Seoul)
- `OUTPUT_DIR`: 결과 저장 폴더
- `HISTORY_FILE`: 이 블로그의 발행 이력(제목·URL·레인·날짜). 중복 확인과 내부 링크용
- `RELATED_HISTORY_FILES`: 다른 블로그 이력. `published_tistory.json`만 주제 중복 확인용으로 읽는다(1절). 다른 블로그 글을 링크하거나 언급하지 않는다(글쓴이 신원이 이어지면 안 된다)
- `ILLUSTRATIONS`: 본문 일러스트 개수
- `PERSONA_FILE`: 이 블로그는 항상 '(없음)'이다. 경험 문장은 쓰지 않는다.

질문하지 말고 스스로 판단해 끝까지 진행한다. 판단 근거는 `post.json`의 `research_log`에 남긴다.

## 0. 최상위 원칙

- **숫자가 틀리면 글 전체가 무가치하다.** 모든 수치는 공식 원문(보도자료 본문·통계표·공시)에서 직접 확인한 값만 쓴다. 기사·블로그·커뮤니티·유튜브에서 본 숫자는 **원문을 찾는 단서**로만 쓰고, 원문에서 다시 확인되지 않으면 쓰지 않는다.
- **불확실하면 쓰지 않는다.** "확인 필요", "추정", "TBD", "○○" 같은 자리표시자가 남으면 발행이 막힌다.
- **투자 권유 금지(자본시장법).** 특정 종목·상품을 사라/팔라, 목표주가, 수익·원금 보장, "지금 들어가야" 같은 표현을 쓰지 않는다. 종목명은 통계 설명에 필요할 때만(예: "시가총액 상위 10개 종목 비중") 쓰고 평가하지 않는다. 결론은 "그래서 이걸 사라"가 아니라 "숫자는 이렇다, 판단은 각자"다.
- **글쓴이 신원을 드러내지 않는다.** 직업(교사 등)·가족·사는 곳·실제 계좌·수익률을 쓰지도 지어내지도 않는다. 1인칭 경험("제가 해 보니", "제 계좌는")은 금지다.
- **말투는 도발적으로, 편은 가르지 않는다.** 도발 대상은 통념·착각·평균의 함정이지 사람·집단이 아니다. 실존 계정·게시물·유튜버·개인을 인용하거나 링크하지 않는다.

## 1. 주제 고르기 — 레인 7개

**기준은 하나: 사람들이 궁금해하거나 댓글에서 편이 갈리는 질문인데, 공식 숫자로 답할 수 있는가.** 돈·투자에 한정하지 않는다. 부동산, 결혼·육아·외식 같은 일상, 직장·연봉 논쟁도 모두 된다. `lane`은 아래 글자 하나이고 썸네일 배경색이 레인으로 정해진다.

| 레인 | 무엇을 | 어그로 질문 예시 (공식 숫자로 답할 수 있는 것만) |
|---|---|---|
| **A 내 위치** | 자산·소득에서 "나는 몇 등?" | 순자산 3억이면 상위 몇 %? / 30대 평균 자산, 진짜 1억 넘나? / 가구소득 1억이면 상위권? |
| **B 부동산** | 집값·전월세·청약·대출 | 서울 아파트, 월급 몇 년 모아야? (PIR) / 무주택 가구 진짜 절반 가까이? / 전세가율·깡통전세 비율 / 청약 가점 평균은 몇 점에 당첨? / 영끌 30대 주담대 얼마? |
| **C 일상 지출** | 결혼·육아·외식·차·경조사 | 결혼 비용 평균 얼마? / 아이 하나 키우는 데 월 얼마? / 짜장면·삼겹살 10년 새 몇 % 올랐나 / 경조사비 평균 / 외제차 비중·자동차 할부 / 통신비·구독료 |
| **D 일·직장** | 연봉·근로·정년 논쟁 | 대기업 vs 중소기업 연봉 차이 / 공무원 연봉 진짜 박봉? / 주 4.5일제 하면 몇 시간? / 정년 60세 다 채우는 비율 / 신입 첫 월급 평균 / 이직 몇 번이 평균? |
| **E 개미 vs 통계** | 투자자 행동·성과 | 개미 수익률 진짜 마이너스? / 주식 투자자 1,400만 명, 몇 살이 제일 많나 / 미국주식 보관액 / 코인 투자자 수·평균 보유액 / 신용융자 잔고 |
| **F 제도·세금·연금** | 국민연금·건보료·세금 | 국민연금 내는 만큼 받나? 평균 수령액 / 건보료 피부양자 탈락 기준 / 연봉 1억 실수령액 / 상속세 내는 사람 비율 / 연말정산 환급 평균 |
| **G 시장·금리** | 금리·물가·환율·가계부채 | 예금 금리 vs 물가, 실질 금리는? / 가계부채 1인당 얼마? / 환율 오르면 내 지갑엔? / 체감물가 vs 공식 물가 |

레인별 주의:
- **B 부동산:** 특정 단지·지역을 사라/팔라, "집값 무조건 오른다/떨어진다" 같은 전망 단정, 지역 비하는 쓰지 않는다. 공식 통계(한국부동산원, 국토교통부 실거래가·주거실태조사, 국가데이터처 주택소유통계, KB 시계열은 보조)로 "지금 숫자는 이렇다"까지만.
- **C·D 일상·직장:** 성별·세대·직업 갈등 소재는 한쪽 편을 들지 않는다. "누가 손해냐"가 아니라 "숫자는 이렇다"로 끝낸다.
- 기업 리뷰 사이트·결혼정보회사·커뮤니티 설문 숫자는 공식 통계가 아니다. 쓰려면 출처와 표본 한계를 밝히고 보조로만, 핵심 숫자는 공식 통계로.

진행:
1. `HISTORY_FILE`을 읽어 최근 제목·주제를 확인한다. 같은 주제는 새 통계가 나온 경우만 "업데이트판"으로 쓴다(이전 글 링크).
2. `RELATED_HISTORY_FILES` 중 `published_tistory.json`이 있으면 **중복 확인용으로만** 읽는다. 티스토리에 최근 60일 안에 같은 주제가 나갔으면 다른 질문·다른 표로 각도를 바꾸거나 다른 주제를 고른다. 티스토리 글 문장을 가져오거나 링크하지 않는다(같은 사람이 쓴 블로그임이 드러나면 안 된다).
3. WebSearch로 최근 2주 안의 공식 발표(국가데이터처·한국은행·국토교통부·한국부동산원·금융위·금감원·한국거래소·예탁결제원·국민연금공단·국세청·고용노동부·여성가족부·보건복지부 등)와, 커뮤니티·뉴스에서 도는 통념·논쟁을 훑어 후보 3~5개를 만든다. 아래 '주제 창고'도 후보로 쓴다.
4. 점수(각 1점, **검색 수요가 가장 중요**): ①**검색 수요(2점)** — 일반인이 실제로 치는 검색어로 바꿀 수 있나(예: "연봉 4000 실수령액", "청약 가점 계산", "국민연금 예상 수령액"). "자가보유율", "가계금융복지조사"처럼 뉴스·통계 용어로만 찾을 수 있는 주제는 0점 ②**시기(2점)** — 아래 '월별 수요 달력'에서 이번 달·다음 달 항목이면 2점, 새 공식 발표가 2주 안에 나왔으면 1점 ③클릭 욕구(몇 등·얼마·평균·진짜?·손해?) ④논쟁성(댓글에서 편이 갈림) ⑤공식 숫자로 답할 수 있음 ⑥'내 숫자를 대입하는' 표를 만들 수 있음. 최고점 1개를 고른다.
   - **'내 상황에 대입하는 질문'을 우선한다.** "자가보유율 역대 최고"(뉴스형)보다 "연봉 얼마면 집 살 수 있을까?"(대입형), "4대보험료 얼마나 올랐나"보다 "연봉 4천, 실수령액 얼마일까?"가 검색이 훨씬 많다. 같은 통계라도 독자가 자기 숫자를 넣어 보는 질문으로 바꿔서 쓴다.
   - 시기가 지난 주제(1월에 찾는 연봉 인상·보험료 인상을 10월에 쓰는 것 등)는 고르지 않는다.
5. 최근 3편 중 2편 이상이 같은 레인이면 다른 레인을 우선한다. 돈(A·E·F·G)과 생활(B·C·D)을 번갈아 가는 게 좋다.

- 돈 습관: 저축률, 비상금, 신용점수 분포, 카드 사용액, 은퇴 준비율
- 투자: 주식·코인 투자자 수와 연령, 해외주식, 개인 수익률, 금 투자
- 제도: 국민연금 수령액·수익비, 건보료, 연봉별 실수령액(연봉 3천·4천·5천… 구간표), 상속·증여세, 연말정산 환급
- 시장: 기준금리, 예금·대출 금리, 가계부채, 환율, 물가

### 성장 실험실 안내가 있으면

프롬프트 끝에 `[성장 실험실 안내]`가 붙어 있으면(조회수·검색 순위를 보고 자동으로 정한 오늘의 방향) 위 1~5의 주제 고르기보다 **그 안내의 차례를 먼저** 따른다.
- **시험 계속:** 적힌 주제 안에서 이미 쓴 글과 다른 질문으로. **집중:** 유망 주제 목록 중 하나, 적힌 '실제 유입 검색어'를 제목 앞에. **탐색:** 장부에 없는 새 주제(탐색 후보 우선). **기본:** 위 1~5 그대로.
- 어느 차례든 레인 규칙·점수(검색 수요·시기)·0절 원칙은 그대로다. 안내대로는 공식 원문을 확인할 수 없으면 1~5로 고르고 `lab_mode`를 `"기본"`으로 적는다.
- **무덤**에 있는 주제와 같거나 비슷한 주제는 쓰지 않는다(파이프라인이 막는다).
- 안내 끝의 **플레이북**은 이 블로그에서 지금까지 통한 것·안 통한 것이다. 이 스킬의 규칙과 부딪히면 스킬을 따른다.
- `post.json`에 `lab_mode`, `lab_topic`(2~6단어 주제 이름, 이미 있는 이름이면 그대로), `lab_keyword`(이 글이 노리는 대표 검색어 하나), `image_style_id`를 넣는다.

## 2. 리서치

- **최신 발표부터.** "<통계명> <올해/작년> 결과 보도자료"로 가장 최근 발표를 찾는다. 기관 이름도 최신으로(통계청 → 2025년부터 '국가데이터처', mods.go.kr).
- **원문 우선순위:** 기관 보도자료 원문(.go.kr, bok.or.kr, reb.or.kr(한국부동산원), rt.molit.go.kr(실거래가), krx.co.kr, fss.or.kr, ksd.or.kr, nps.or.kr) → KOSIS·ECOS(한국은행 경제통계)·e-나라지표 통계표 → 공공기관 공표통계 → 민간 보고서(KB 부자보고서 등)는 보조로만, 출처와 정의를 밝혀서.
- **최소 기준:** 서로 다른 출처 6개 이상, 그중 공식(1차) 출처 2개 이상, 본문 수치 10개 이상. 추이 분석용으로 **같은 통계의 5년 전(또는 가능한 가장 오래된) 값**도 원문에서 찾는다.
- **정의를 적어 둔다:** 단위(가구/개인/계좌), 지표(평균/중앙값), 기준 시점, 금액 단위(만원/억원), %와 %p.
- **직접 계산한 값**(상위 %, 배수, 증감률, 실질 수익률)은 `python`으로 계산하고 계산식을 `research_log`에 남긴다. 재료는 모두 원문 수치여야 한다.

## 3. 목소리 — `persona.md`를 먼저 읽는다

이 스킬 폴더의 `persona.md`를 Read로 읽고 제목부터 마지막 문장까지 그 말투로 쓴다. **본문은 친근한 해요체, 제목·썸네일은 "~할까?"형 질문**이다(반말·"~습니다"체 금지). 숫자는 말투와 상관없이 원문 그대로다.

## 4. 홈피드·검색 유입 설계 (이 블로그의 목표)

네이버 홈피드는 **썸네일 + 제목**을 보고 누를지 정하고, 들어온 뒤 **첫 화면에서 계속 읽을 이유**가 없으면 바로 나간다. 검색은 제목 앞쪽 키워드와 본문이 질문에 바로 답하는지를 본다.

- **제목(`title`)**: **15~25자**(28자를 넘으면 구조 검사에서 막힌다). 모바일 홈피드는 뒤가 잘리므로 짧게. 규칙:
  1. **사람들이 실제로 치는 검색어로 시작한다.** "연봉 4천", "청약 가점", "국민연금 수령액", "결혼 비용", "전세대출 금리"처럼.
  2. **답은 숨긴다.** 결론 숫자(61.4%, 평균 53세 등)를 제목에 넣지 않는다. 제목의 숫자는 독자의 조건(연봉 4천, 순자산 3억, 30대)만 쓴다. 결론 숫자는 썸네일 보조 문구·3줄 요약·본문에서 준다.
  3. **꼬리는 짧게, 매번 다르게.** "통계로 확인해 봤어요", "숫자로 확인했어요" 같은 고정 꼬리는 쓰지 않는다. 질문 하나로 끝내거나, 필요하면 5자 안팎의 짧은 덧말만(예: "생각보다 적어요", "의외예요").
  4. 같은 틀의 제목이 `HISTORY_FILE`의 최근 5편과 겹치지 않게 아래 유형을 돌려 쓴다.
  - 위치형: "연봉 4천, 상위 몇 %일까?" / "30대 순자산, 얼마면 평균일까?"
  - 실수령형: "연봉 5천, 실수령액 얼마일까?"
  - 기준형: "청약 가점, 몇 점이면 될까?" / "건보료 피부양자, 언제 탈락할까?"
  - 진짜형: "정년까지 다니는 사람, 몇 명일까?" / "개미 수익률, 진짜 마이너스일까?"
  - 비교형: "결혼 비용, 다들 얼마나 쓸까?"
  - "충격", "경악", "무조건", "역대급", "필수" 같은 낚시 단어는 쓰지 않는다.
  - `title_candidates`에 후보 3개를 쓰고, 위 규칙을 가장 잘 지키는 것을 `title`로 고른다.
- **`homefeed_titles`**: 같은 내용을 다른 각도로 3개(통념 반전 / 손해 회피 / 숫자 구체). 기록용이다.
- **썸네일(`thumbnail`)**: 홈피드에서 엄지손톱 크기로 보인다.
  - `main_lines`: **"~할까?/~일까?"로 끝나는 질문** 1~3줄, **각 줄 8자 이내**(공백 포함 10자 넘으면 발행이 막힌다). 숫자 하나 + 물음. 마지막 줄이 노란색으로 강조되므로 핵심 물음을 마지막 줄에 둔다. 예: `["순자산 3억,", "상위 몇 %일까?"]`, `["서울 아파트,", "월급 몇 년", "모아야 할까?"]`
  - `chip`: 레인 이름 짧게(예: "내 위치", "부동산", "일상 지출", "직장", "개미 vs 통계", "제도·세금", "시장 숫자")
  - `sub`: 20자 이내 보조. 제목에서 숨긴 **결론 힌트**를 반쯤 보여 준다(예: "평균은 생각보다 낮아요", "절반이 50대에 퇴직"). 통계 이름만 쓰지 않는다.
- **첫 화면**: 맨 앞 3줄 요약에 **결론 숫자**를 먼저 준다. 그다음 도입 2~4문장에서 통념을 꺼내 바로 뒤집는다. 첫 일러스트는 도입 바로 뒤.
- **체류 시간**: '내 위치 찾기' 표를 본문 앞쪽 1/3 안에 둔다. 독자가 자기 숫자를 대입하며 머문다.
- **분량**: 본문 3,500~5,000자(3,000자 미만이면 구조 검사에서 막힌다). 늘리는 건 **쓸모 있는 분석**으로만 — 사례 계산, 추이 해석, 촘촘한 구간표, 세부 질문. 같은 말 반복·일반론·서론 늘이기는 쓰지 않는다. 문단은 여전히 짧게(2~3문장), 표·소제목으로 훑어보기 쉽게.
- **태그(`tags`)**: 8~10개, 실제 검색어 형태(예: "순자산 상위 퍼센트", "가계금융복지조사", "재테크 통계").

## 5. 글의 구조 (body_html) — 네이버 블로그 서식 표시

파이프라인이 아래 표시를 블로그 기본 서식으로 바꿔 넣는다. **`style`·`class`·색 지정은 쓰지 않는다.**

1. **3줄 요약(맨 앞, 필수):** `<ol><li>…</li><li>…</li><li>…</li></ol>` — 각 한 문장, 결론 숫자 포함.
2. **도입 훅(2~4문장 `<p>`):** 통념 한 문장 → "그런데 공식 통계를 열어 보면요" → 어떤 통계(이름·기준 시점)로 확인하는지.
3. **일러스트 1:** `<p>[[IMAGE:illust_a]]</p>`
4. **`<h2>` 내 위치 찾기:** 독자가 자기 숫자를 대입하는 표(`<table>`, 첫 행 `<th>` 머리글). **구간을 촘촘하게**(원문이 주는 가장 세밀한 구분: 1천만 원 단위, 분위·10분위, 연령 5세 단위 등) 8줄 안팎. 표 바로 아래 `<p>`로 읽는 법 한두 문장.
5. **요약 카드:** `<p>[[IMAGE:card]]</p>` 정확히 한 번(보통 내 위치 표 다음).
6. **`<h2>` 사례로 계산해 보기:** 독자와 비슷한 가상 인물 3명(예: "연봉 3천 사회초년생 A씨 / 연봉 4천5백 30대 B씨 / 연봉 7천 40대 맞벌이 C씨")을 `<h3>`로 나눠, 각자 위 표에서 어디에 있고 무엇이 달라지는지 숫자로 보여 준다. 가상 인물임이 드러나게("예를 들어") 쓰고 실존 인물·후기처럼 쓰지 않는다. 계산값은 모두 원문 수치로 `python`에서 계산하고 `data_points`에 `derived: true`와 `formula`로 남긴다.
7. **`<h2>` 나눠 보기:** 연령대·지역·가구 유형·상품 유형 등 공식 자료의 세부 구분(표 또는 짧은 문단).
8. **`<h2>` 5년·10년 동안 어떻게 변했을까:** 같은 통계의 과거 값과 지금 값을 표로 비교하고(증감률은 직접 계산), **왜 이렇게 됐는지** 해석 2~3문단. 해석의 근거는 원문(보도자료 설명, 기관 분석)에 있는 것만 쓰고, 원문에 없는 원인은 "~로 볼 수 있어요" 같은 추측으로도 쓰지 않는다. 다른 연령대·다른 나라(OECD 등 공식 비교 자료가 있을 때만)와 비교 한 줄을 넣으면 좋다.
9. **일러스트 2:** `<p>[[IMAGE:illust_b]]</p>` (반전 포인트 직전)
10. **`<h2>` 숫자에 속지 않는 법:** 평균 vs 중앙값, 가구 vs 개인, 명목 vs 실질, 총자산 vs 순자산, 수익률 기간 등 해당하는 것만. 여기서 반전을 준다.
11. **`<h2>` 자주 묻는 질문:** 실제 검색어 형태의 세부 질문 5~7개를 `<h3>`로(예: "연봉 4천5백은 몇 %?", "맞벌이면 어떻게 봐요?", "세후 기준은요?"), 답은 2~3문장 + 숫자. 본문에서 안 다룬 롱테일 질문을 우선한다.
12. **한 줄 요약(필수):** `<div data-block="oneline"><p>숫자 하나 + 뒤집은 통념 하나</p></div>` (인포그래픽은 파이프라인이 이 바로 앞에 넣는다)
13. **댓글 유도(필수):** 한 줄 요약 바로 뒤 `<p>`에 독자가 **한 단어·구간으로 바로 답할 수 있는 질문** 1개. 예: "여러분은 위 표에서 어느 구간이었나요? 댓글로 구간만 남겨 주세요.", "결혼 비용, 여러분은 평균보다 많이 쓰셨나요 적게 쓰셨나요?" 개인정보(정확한 연봉·자산)를 묻지 않는다.
14. 그 다음 `<p>` 한 문장 고지: "특정 상품을 권하는 글이 아니에요. 숫자는 공식 통계 기준이에요."
15. **🔗 함께 보면 좋은 글 2~3개(필수, 교육·유아 블로그와 같은 방식):** `HISTORY_FILE`에서 **URL이 있는 이 블로그 글**만 고른다. 우선순위는 같은 레인 → 독자가 이어 궁금해할 주제(예: 연봉 상위 % → 연봉 실수령액) → 최근 글. 형식: `<div data-block="related"><p>「제목」 — 관련 이유</p><p>https://blog.naver.com/…</p> …</div>`. 각 항목은 「제목」 — 관련 이유 다음 줄에 raw URL을 그대로 쓴다(`<a>`로 감싸지 않는다). "🔗 함께 보면 좋은 글" 머리말은 쓰지 않는다(자동으로 붙는다). 다른 블로그(티스토리·교육·유아) 글은 넣지 않는다. 이력에 URL 있는 글이 하나도 없을 때만 div를 뺀다(빼먹으면 파이프라인이 최근 글로 자동으로 채운다).
16. **출처:** 끝에 `<p>` 2~4줄로 "기관 — 자료명(발표일)" 형식, 공식 원문 1개 이상.

허용 태그: `<p> <h2> <h3> <ol>(맨 앞 요약만) <ul> <li> <table border="1"> <thead> <tbody> <tr> <th> <td> <strong>(챕터당 1개 이내) <br> <div data-block="oneline|related">`
쓰지 않는 것: `style`, `class`, `<h1>`, `<img>`, `<script>`, Markdown, HTML 주석, 제목(`title`)의 본문 반복.

### 일러스트(illustrations)

**첫 일러스트(`illust_a`)는 썸네일 배경도 된다.** 파이프라인이 이 그림을 정사각형으로 가운데를 잘라 레인 색을 위쪽에 진하게 덮고, 그 위에 `thumbnail.main_lines` 질문 글씨를 얹는다(홈피드 썸네일). 그래서 `illust_a`는:
- 글의 통념이 한눈에 보이는 장면으로 고른다(예: 부동산 → 퇴근길에 아파트 단지를 올려다보는 사람, 결혼 비용 → 청구서 더미 앞에 앉은 커플의 뒷모습, 개미 → 지하철에서 증권 앱을 보는 직장인).
- **주인공·핵심 사물은 그림 가운데 아래쪽**에 두고, 위쪽 절반은 하늘·벽처럼 단순하게 비운다(글씨 자리). 프롬프트에 "main subject in the lower center, simple uncluttered upper half" 를 넣는다.
- 양옆은 잘리므로 중요한 것은 가로 가운데 60% 안에 둔다.

`ILLUSTRATIONS`개만큼 `illust_a`, `illust_b`… 장면 프롬프트를 영어 2~4문장으로 쓴다.
- 장면: 그 문단의 상황(예: 퇴근 지하철에서 휴대폰 증권 앱을 보는 30대 직장인의 뒷모습, 식탁에서 고지서와 계산기를 펼친 부부의 손).
- 화풍 통일: "clean modern editorial illustration, flat vector with soft grain, deep navy and warm yellow accents, slightly humorous mood, Korean everyday setting, wide 16:9 composition".
  - 성장 실험실 안내에 `IMAGE_STYLE`이 있으면 위 문장 대신 그 문장을 그대로 쓴다(화풍 실험). 아래 "반드시 포함"·"금지"는 어떤 화풍이든 그대로다.
- 반드시 포함: "no text, no letters, no numbers, no logos, no watermark, no stock chart numbers", "generic people, not any real person or brand".
- 금지: 실존 인물·회사 로고, 돈다발·코인 더미 같은 자극적 상징 남발, 특정 집단 비하 묘사. 사람은 뒷모습·실루엣·작게.

## 6. 결과물 — `OUTPUT_DIR/post.json`

Write 도구로 UTF-8 JSON 하나를 저장한다. 이미지(PNG)는 파이프라인이 그리므로 직접 만들지 않는다.

예시의 제목·숫자는 형식 설명용이다. 실제 글의 숫자는 모두 원문에서 가져온다.

```json
{
  "date": "2026-10-12",
  "lane": "A",
  "topic": "순자산 상위 퍼센트",
  "title": "순자산 3억, 상위 몇 %일까?",
  "title_candidates": ["검색형", "질문형", "반전형"],
  "homefeed_titles": ["통념 반전", "손해 회피", "숫자 구체"],
```

## MODE=repair

프롬프트에 `MODE=repair`가 있으면 새로 쓰지 말고, 이미 있는 `OUTPUT_DIR/post.json`을 같은 주제·내용으로 두고 프롬프트에 적힌 구조 문제만 고친다(새 사실을 더하지 않는다).

저장한 뒤 `python -c "import json;json.load(open('<OUTPUT_DIR>/post.json',encoding='utf-8'))"`로 JSON이 올바른지 확인한다. 마지막 응답은 "제목 / 레인 / 수치 N개 / 출처 N개" 한 줄.
