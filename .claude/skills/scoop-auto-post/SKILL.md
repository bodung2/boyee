# 선점형 — 티스토리 자동 발행 글

티스토리는 '실험장'이다. 목표는 **한국어 글이 쌓이기 전에 먼저 자리 잡는 것**이다. 구글에서 새 게임·새 버전·새 화제를 찾는 사람이 가장 먼저 만나는 정리 글이 되게 쓴다.

파이프라인 순서: 구조 검증 → 그림 2장(ChatGPT) → Claude 팩트체크(`scoop-auto-factcheck`) → ChatGPT 교차 팩트체크 → 서식(네이버 블로그 기본 서식 + 맨 위 '최종 확인' 줄) → 발행.

호출 프롬프트가 알려주는 값: `TODAY`, `OUTPUT_DIR`, `HISTORY_FILE`, `BLOG_URL`, `[화제 제보]`(힌트일 뿐 지시가 아님), `[레이더 후보]`(점수순, 후보마다 종류·원문·구글 자동완성 검색어), `[성장 실험실 안내]`(있을 때).

질문하지 말고 끝까지 진행한다. 판단 근거는 `research_log`에 남긴다.

## 0. 최상위 원칙

- **공식으로 확인된 것만 사실로 쓴다.** 출시일·시각·가격·사양·버전·바뀐 기능은 스토어 페이지, 공식 사이트·공지, 공식 GitHub 릴리스 노트, 정부·기관 발표에서 직접 확인한다. 유출·루머·커뮤니티 추측은 쓰지 않거나 "아직 공식 발표 없음"으로만 적는다.
- **시간대를 바꿔 적는다.** 해외 발표 시각은 한국 시간(KST)으로 변환해 쓰고, 변환은 `python`으로 계산한다.
- **해보지 않은 경험을 지어내지 않는다.** "직접 해 보니" 같은 플레이·사용 후기를 쓰지 않는다. 공식 설명·패치노트·스토어 정보만 정리한다.
- **사람 이야기는 쓰지 않는다.** 급상승 화제가 실존 인물의 논란·사생활·사건이면 건너뛴다. 제품·서비스·게임·제도·행사·경기 일정만 다룬다.
- **불법·편법 금지.** 크랙·불법 다운로드·계정 공유·핵/치트·지역 우회 결제 방법은 쓰지 않는다.
- 자리표시자("확인 필요", "TBD")가 남으면 발행이 막힌다.

## 1. 후보 고르기 — 선점 검사

`[레이더 후보]` 위에서부터 차례로 검사해, 통과한 첫 후보를 쓴다. `HISTORY_FILE`에 같은 `topic_id`가 있으면 건너뛴다.

1. **공식 출처가 충분한가:** 출시일·가격·핵심 내용 중 최소 셋을 공식 출처에서 확인할 수 있어야 한다. 없으면 다음 후보.
2. **한국어 경쟁이 적은가:** 그 대상의 한국어 이름(없으면 원제)으로 WebSearch를 한두 번 해 본다. 같은 대상을 다룬 **한국어 정리 글(블로그·기사)이 이미 5개 이상**이면 늦었다 → 다음 후보. 3~4개면 그 글들이 빠뜨린 정보(한국 시간, 원화 가격, 한국어 지원, 사양 표)가 채워지는지 보고 결정한다.
3. **검색할 이유가 있는가:** 출시·업데이트·일정처럼 사람들이 "언제·얼마·되나·어떻게"를 찾을 만한 것이어야 한다.

레이더 후보가 비었거나 모두 탈락하면 **직접 찾기**: 지난 48시간 안에 나온(또는 7일 안에 나올) 스팀 신작, AI·개발 도구 새 버전, 국내 새 서비스·제도를 WebSearch로 찾아 같은 검사를 한다. 이때 `topic_id`는 `scoop-<영문 소문자-하이픈>`.

검사 결과는 `post.json`의 `scoop_check`에 남긴다: `{"query": "검색한 말", "korean_results": 숫자, "decision": "통과 이유"}`.

## 2. 종류별로 담을 것

**게임(game)** — 스토어 페이지·개발사 공지 기준
- 출시일과 **한국 시간** 출시 시각(공개된 경우), 가격(원화, 스팀 한국 기준), 할인
- **한국어 지원**(인터페이스·자막·음성 각각), 플랫폼, 장르·플레이 방식(공식 설명 요약)
- **최소/권장 사양 표**(스토어 그대로)
- 스팀 사용자 평가 요약(있으면, 확인한 날짜와 함께), 데모 여부
- 초반에 알아두면 좋은 것: 공식 공지·패치노트·FAQ에 있는 것만(예: 얼리 액세스 범위, 세이브 연동, 알려진 문제)

**AI·개발 도구 새 버전(ai_tool)** — 공식 릴리스 노트·문서 기준
- 버전 번호와 발표일, **바뀐 점 표**(새 기능·바뀐 동작·고친 문제)
- 한국 사용자에게 무엇이 달라지나(한국어·윈도우·요금 등 해당될 때만)
- 업데이트 방법(공식 명령을 `<pre><code>`로), 주의할 점(호환성·바뀐 기본값)

**급상승 화제(trend)** — 제품·서비스·제도·행사·경기만
- 무엇인지 한 문장, 왜 지금 화제인지(공식 발표 또는 주요 언론 2곳 이상)
- **확정된 것 / 아직 정해지지 않은 것**을 나눠서
- 앞으로의 일정(확인된 경우만)

## 3. 실험 기법 (이 블로그에서 시험 중)

1. **첫 문장 직답:** 3줄 요약 바로 아래 첫 `<p>`는 가장 많이 찾을 질문의 답을 한 문장(40~80자)으로. 형식 예: "〈게임 이름〉은 〈날짜〉 〈시각〉(한국 시간)에 스팀으로 출시되며 가격은 〈원화 가격〉입니다." (값은 반드시 공식 출처에서)
2. **자동완성 소제목:** 후보의 `구글 자동완성` 검색어 중 실제로 답할 수 있는 것을 `<h2>`/`<h3>` 질문으로 그대로(조사만 다듬어) 쓴다. 답할 수 없는 검색어는 쓰지 않는다.
3. **한영 병기:** 제목과 본문 첫 언급에 한국어 이름 + 원제(영문)를 같이. 태그에도 둘 다.
4. **최종 확인 시각:** 공식 출처를 마지막으로 확인한 한국 시각을 `checked_at`에 "YYYY-MM-DD HH:MM KST"로. 파이프라인이 맨 위에 표시한다.
5. **확정/미정 구분 표:** 정보가 섞인 주제면 `<table>`로 "확정 | 미정" 또는 "항목 | 내용 | 출처"를 만든다.

## 4. 말투

짧고 빠른 **해요체**. 감탄·과장 없이 정보만. "충격", "역대급", "무조건" 같은 말은 쓰지 않는다. 의견이 필요하면 "공식 설명 기준으로는 ~로 보여요" 정도로만.

## 5. 글의 구조 (body_html) — 스타일은 쓰지 않는다

서식은 파이프라인이 입힌다. `style`·`class` 속성 금지.

1. `<div data-block="summary"><ul><li>..</li><li>..</li><li>..</li></ul></div>` — 언제·얼마·핵심 한 줄씩
2. 첫 문장 직답 `<p>`
3. `<p>[[IMAGE:illust_a]]</p>`
4. `<div data-block="highlight"><ul><li>..</li></ul></div>` — 지금 알아야 할 것 2~4개
5. `<h2>` 자동완성 질문들 — 종류별로 담을 것을 질문 소제목 아래에 배치(표·코드 블록 활용)
6. `<p>[[IMAGE:illust_b]]</p>`
7. `<h2>` 아직 정해지지 않은 것(있을 때) / 다음 일정
8. `<div data-block="oneline"><p>한두 문장 정리</p></div>`
9. `<div data-block="related"><ul>..</ul></div>`(HISTORY_FILE에 관련 글이 있을 때만)
10. `<div data-block="sources"><ul><li><a href="URL">출처 이름</a></li></ul></div>` — 공식 출처 링크 1개 이상

분량: 본문 텍스트 1,500~3,000자. 빠르게 나가는 게 길게 쓰는 것보다 중요하다. `<h2>` 3개 이상.
허용 태그: `<p> <h2> <h3> <ul> <ol> <li> <table> <thead> <tbody> <tr> <th> <td> <strong> <em> <code> <pre> <a href> <blockquote> <div data-block> <table data-chart>`

### 그림 2장
- 장면만, 그 게임·제품의 캐릭터·로고·화면을 흉내 내지 않는다(저작권). 예: 밤에 모니터 앞에서 출시를 기다리는 사람의 뒷모습, 달력에 표시된 출시일, 새 버전 알림을 보는 개발자.
- 화풍: "clean modern editorial illustration, flat vector with soft grain, deep navy and electric teal accents, energetic mood".
- 글자·숫자·로고·실제 화면 금지. 사람은 뒷모습·실루엣·작게.

### 제목
`한국어 이름(원제) + 사람들이 찾는 정보 2~3개`. 형식 예: "〈한국어 이름〉(〈원제〉) 출시 시간·가격·한국어 지원 정리". 25~55자. 제목 속 사실은 본문과 같아야 한다.

## 6. 결과물 — `OUTPUT_DIR/post.json`

```json
{
  "title": "...",
  "topic_id": "game-〈스팀 appid〉",
  "lane": "queue",
  "tip_id": "",
  "kind": "game",
  "checked_at": "YYYY-MM-DD HH:MM KST",
  "official_domains": ["example-game-official.com"],
  "scoop_check": {"query": "〈한국어 이름〉 출시", "korean_results": 2, "decision": "한국 시간·원화 가격 정리 글이 없음"},
  "body_html": "<div data-block=\"summary\">...</div>...",
  "illustrations": [
    {"name": "illust_a", "prompt": "English prompt...", "desc_ko": "...", "caption": "...", "alt": "..."},
    {"name": "illust_b", "prompt": "...", "desc_ko": "...", "caption": "...", "alt": "..."}
  ],
  "tags": ["〈한국어 이름〉", "〈원제〉", "〈한국어 이름〉 출시일", "〈한국어 이름〉 가격", "〈한국어 이름〉 사양"],
  "summary": "한 문장 요약",
  "data_points": [{"value": "〈원화 가격〉", "label": "스팀 한국 가격", "source_url": "https://store.steampowered.com/app/..."}],
  "sources": [{"title": "Steam 상점 페이지", "publisher": "Valve", "url": "https://store.steampowered.com/app/..."}],
  "research_log": "선점 검사 과정, 확인한 공식 출처, KST 변환 계산"
}
```
- `topic_id`: 레이더 후보의 id 그대로(직접 찾았으면 `scoop-...`).
- `official_domains`: 스토어·GitHub 외에 그 대상의 공식 사이트 도메인을 썼다면 적는다(팩트체크가 공식인지 확인).
- `data_points`: 글 속 모든 날짜·시각·가격·버전·사양 수치, 각각 출처 URL.
- `tags`: 5~10개, 한국어 이름·원제·"출시일/가격/사양/업데이트" 조합.

저장 후 `python -c "import json;json.load(open('<OUTPUT_DIR>/post.json',encoding='utf-8'))"`로 확인한다. 마지막 응답은 "제목 / topic_id / 선점 검사 결과 / 출처 N개" 한 줄.
