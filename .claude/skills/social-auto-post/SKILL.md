# 블로그 글 → 인스타그램·쓰레드 (자동 발행 모드)

이 스킬은 `edu-social-adaptation`의 **자동 발행 버전**이다. 파이프라인이 블로그 글을 발행한 직후 호출하고,
여기서 만든 `social.json`은 그날 저녁 예약 작업이 **사람 검토 없이** 인스타그램·쓰레드에 올린다
(SR은 그 사이에 `social.json`을 직접 고칠 수 있다).

호출 프롬프트가 알려주는 값:
- `OUTPUT_DIR`: 그날 글 폴더. `post.json`(발행된 블로그 글)이 있고, 결과 `social.json`을 여기에 쓴다.
- `BLOG_URL`: 발행된 블로그 글 주소(실제 주소 — 그대로 쓴다)
- `PROFILE`: `edu`(교육 블로그) 또는 `childhood`(유아교육 블로그)
- `ACCOUNT`: 소셜 계정 이름(없을 수 있음)

부재 중 자동 실행이므로 질문하지 말고 끝까지 진행한다.

## 0. 절대 원칙

1. **사실은 post.json에서만.** 제목·본문(`body_html`)·요약 카드(`card`)에 있는 사실·수치·날짜·고유명사만 쓴다.
   웹 검색을 하지 않는다. 새 숫자·주장·최신 정보를 지어내지 않는다. 후킹을 위해 과장·왜곡하지 않는다.
   ⚠️ 파이프라인이 소셜 글 속 **모든 숫자가 블로그 글에 실제로 있는지** 기계적으로 검사한다. 블로그에 없는 숫자(계산해서 만든 퍼센트·합계 포함)가 하나라도 있으면 그 글은 버려진다.
2. **복붙 금지(재가공 강제).** 블로그 문장을 그대로 잘라 붙이지 않는다. 인스타 캡션과 쓰레드 글도 서로 다른 문장으로 쓴다
   (같은 팔로워가 두 채널을 함께 본다). 재료(5토막)는 같이 쓰되 문장은 채널마다 새로 쓴다.
3. **사실 안전.** 통계에는 연도·기관을 붙인다("2025년 조사, 교육부"). 확정 안 된 정책은 "예정"·"추진 중"으로 구분한다.
   찬반이 갈리는 쟁점은 원문처럼 균형 있게, 한쪽 편을 들지 않는다. 원문에 없는 효과·성과를 부풀리지 않는다.
4. **경험 위조 금지 + ✍️ 자리 없음.** "제가 겪어보니", "우리 반 아이가" 같은 경험을 지어내지 않는다.
   자동 발행이므로 ✍️ 자리도 만들지 않는다. 현직 교사 관점은 '검증된 사실의 해석' 한 줄까지만.
5. **개인정보.** 학생·학부모·학교를 특정할 정보는 쓰지 않는다. 교사 신원은 숨길 필요 없다(포지션의 강점).
6. **핵심을 뭉뚱그리지 않는다.** 원문의 핵심 수치·명칭·기준·시행일 중 1~2개는 두 채널 모두에 구체적으로 남긴다.
7. **블로그 연결 훅 필수.** 두 채널 모두 끝부분에 `BLOG_URL`을 **글자 그대로 한 번** 넣는다
   ("더 자세한 기준·근거는 블로그에 정리했어요 👉 BLOG_URL"). 주소를 줄이거나 바꾸지 않는다.
8. **유아 글(`PROFILE=childhood`) 추가 가드레일.** '정상/지연', '통과해야', '못하면 발달이 늦다' 같은 진단·판정 표현 금지,
   발달 검사 문항 인용 금지, 조바심 조장 금지(개인차·놀이 중심), 판매·구매 링크 금지. 초등 교사가 보는 유아교육이라는 결을 유지한다.
9. **자리표시자 금지.** `확인 필요`, `TBD`, `○○`, `✍️`, `[이미지` 같은 문구가 남으면 발행이 막힌다.

## 1. 재료: 5토막

post.json을 읽고 아래 5토막을 뽑는다(3단계에서 채널마다 새로 쓴다).

1. **후킹 첫 줄** — 질문형/통념 반전/인상적 숫자 중 하나. 본문이 실제로 답하는 내용이어야 한다(낚시 금지).
2. **정책·정보 내용(현장의 말로, 핵심 2~4줄)** — 공식 명칭, 실제로 이해에 필요한 수치·기준·시행일.
3. **현직 교사 관점 한 줄** — 지어낸 경험 없이 해석으로.
4. **블로그 연결 훅** — `BLOG_URL` 포함.
5. **반응 유도 마무리** — 답하기 쉬운 질문("여러분 학교는 어떤가요? 👇").

## 2. 채널별로 쓰기

문체: 짧은 문장, 잦은 줄바꿈, 친근한 현직 교사 톤, 이모지 절제.

**① 쓰레드(Threads)** — 텍스트가 주인공, 댓글을 부르는 대화체.
- 5토막을 **한 글**로. **공백·줄바꿈·주소 포함 450자 이내**(Threads 한도 500자, 여유를 둔다).
- 핵심 수치는 1~2개로 제한, 블로그 훅은 한 줄.
- `topic_tag`: 주제 태그 1개(띄어쓰기 없이, `#` 없이. 예: `교육정책`, `유아교육`).
- 이미지는 파이프라인이 인포그래픽 1장을 붙인다(글에 이미지 설명을 쓰지 않는다).

**② 인스타그램(Instagram)** — 이미지는 파이프라인이 그 글의 **인포그래픽 1장**을 쓴다(카드뉴스 없음). 캡션은 정보 요약 결.
- 캡션 구조: 도입 훅 1~2줄 → 핵심 요약 3~4줄(인포그래픽을 보며 읽는다는 느낌으로) → 현직 교사 관점 한 줄
  → "저장해두고 필요할 때 보세요" 같은 저장 유도 → 블로그 훅(인스타는 캡션 링크가 눌리지 않으므로
  "자세한 내용은 프로필 링크 또는 아래 주소에서" + `BLOG_URL`) → 댓글 유도 질문.
- 캡션 본문 **1,500자 이내**(해시태그 제외).
- `hashtags`: **10~15개**, 각 항목은 `#`로 시작, 띄어쓰기 없이. 글에 맞게(교육: `#교육정책 #학부모 #현직교사 #초등맘`…,
  유아: `#유아교육 #육아정보 #누리과정 #초등입학준비`…). 판매·브랜드 태그 금지.

## 3. 저장 — OUTPUT_DIR/social.json

Write 도구로 UTF-8 JSON 하나를 저장한다.

```json
{
  "blog_url": "BLOG_URL 그대로",
  "hook": "두 채널 공통으로 잡은 후킹 한 줄(기록용)",
  "threads": {
    "text": "쓰레드 글 전체(450자 이내, BLOG_URL 포함)",
    "topic_tag": "교육정책"
  },
  "instagram": {
    "caption": "인스타 캡션 본문(1,500자 이내, BLOG_URL 포함, 해시태그 제외)",
    "hashtags": ["#교육정책", "#학부모"]
  },
  "facts_used": ["소셜 글에 쓴 수치·명칭과 그것이 나오는 블로그 문장(검수 기록용)"]
}
```

저장 후 Read로 다시 열어 JSON이 올바른지, 글자 수·주소·해시태그 개수를 확인한다.
마지막 응답은 한 줄로: `threads N자 / instagram N자·태그 N개 / 후킹: …`
