# 성장 실험실 주간 리뷰

호출 프롬프트가 알려 주는 값:
- `BLOG`: invest(네이버 투자 블로그) / guide(네이버 생활 절차 블로그) / tistory(티스토리 오류 해결)
- `TODAY`, `INPUT`(review_input.json), `OUTPUT`(review.json을 쓸 경로)

**쓸 수 있는 파일은 `OUTPUT` 하나뿐이다.** 스킬·코드·장부·플레이북 파일을 직접 고치지 않는다. 장부와 플레이북은 파이프라인이
review.json을 읽어 바꾼다. 질문하지 말고 끝까지 진행한다.

## 0. 원칙

- **숫자는 INPUT과 통계 화면 원본에 있는 것만.** 조회수·순위·검색어를 지어내지 않는다. 모르면 "자료 없음"이라고 쓴다.
- **판정은 이미 끝났다.** 주제 상태(유망·중단 등)는 코드 규칙이 정했다(`verdicts`). 여기서 뒤집지 않는다. 할 일은 **왜 그런지** 찾고 **다음에 무엇을 해 볼지** 정하는 것이다.
- **잠긴 규칙은 건드리지 않는다.** 사실 확인·출처 기준, 투자 권유 금지, 글쓴이 신원 비노출, 경험 지어내기 금지, 발달·안전·위험 명령 차단,
  낚시 단어 금지 같은 글쓰기 스킬의 규칙을 약하게 하는 제안·플레이북 문장은 쓰지 않는다. 조회수를 위해 자극적으로 바꾸자는 제안도 금지.
- **글 몇 편으로 단정하지 않는다.** 근거가 3편 미만이면 "가설"로 적는다.
- 리서치에서 읽은 남의 글 문장을 플레이북에 옮겨 적지 않는다(구조·패턴만 요약).
- **`proposals`·`report`·`funnel.evidence`에는 글 제목·글 주소·블로그 이름을 쓰지 않는다.** 이 셋은 공개 저장소의 주간 보고에 올라간다. 글은 주제 이름과 날짜로 가리킨다(예: '청약 가점 주제 10/12 글').

## 1. 자료 읽기

1. `INPUT`을 Read로 읽는다. 중요한 값:
   - `channel`: "정상"이 아니면(데이터 부족·채널 점검) 주제 탓으로 보지 말고 채널 원인부터 본다.
   - `posts`: 글별 `v1`(판정 나이 조회수), `ratio`(블로그 중간값 대비 점수), `best_rank`(네이버 검색 순위, 낮을수록 위), `features`(제목 유형·분량·표·그림·화풍 꼬리표)
   - `verdicts`, `topics`, `graveyard`, `explore_queue`, `experiment`, `experiments_done`, `proposals`(거절된 제안은 다시 내지 않는다)
   - `learned_file`: 지금 플레이북(있으면 Read)
2. `capture_files`(최근 통계 화면 원본, 큰 JSON)를 Read로 연다. `pages[].text`에서 **유입 경로**(검색·홈피드·이웃·외부)와 **유입 검색어**를,
   `responses[].json`에서 검색어·유입 목록처럼 보이는 배열을 찾는다. 파일이 크면 offset/limit으로 나눠 읽는다.

## 2. 막힌 단계 진단 (`funnel`)

하나를 고르고 근거 숫자를 든다.

| 단계 | 신호 |
|---|---|
| 데이터 부족 | 조회수를 읽은 글이 적거나 판정 나이에 이른 글이 적다 |
| 채널 | 블로그 전체 조회 증가가 거의 없음, 검색 순위가 거의 다 상위 100 밖, 색인 안 됨 |
| 수요 | 순위는 괜찮은데(1~10위) 조회가 적다 → 그 검색어를 찾는 사람이 적다 |
| 노출 | 조회가 적고 순위도 낮다(30위 밖) → 키워드 배치·글 구조·경쟁 |
| 클릭 | (홈피드·검색 노출은 있는데) 조회 전환이 낮다 → 제목·썸네일 |
| 읽기 | 들어오긴 하는데 다른 글로 이어지지 않는다(체류·다음 글 자료가 있을 때만) |

꼬리표(`features`)와 점수를 맞대어 보이는 패턴(예: 표 2개 이상 글의 점수 중간값이 높다, '얼마형' 제목이 낮다)을 적는다. 글 3편 미만이면 가설.

## 3. 리서치 (WebSearch·WebFetch)

1. **잘 되는 글 분석:** 유망 주제 1개와 성적이 나쁜 주제 1개의 대표 검색어로 검색해 상위 글 3~5개를 연다.
   제목 길이·형식, 첫 화면(결론이 먼저인가), 표·그림 수, 소제목 구성, 분량을 우리 글과 비교한다.
   - invest·guide: 네이버 검색(블로그·스마트블록) 결과 위주. tistory: 구글·다음 결과 위주.
   - guide: 상위 글이 공식 화면 캡처·표를 몇 개, 어디에 두는지, 첫 문단에서 바로 날짜·금액을 주는지도 본다.
2. **플랫폼 변화:** 최근 1~2달 안의 공식 공지·발표(네이버 검색·블로그 공지, 구글 검색 센터 블로그, 티스토리·다음 공지)에서
   검색·홈피드 노출 방식 변화가 있었는지 확인한다. 있으면 날짜·출처와 함께 적는다.
3. **새 주제 후보(`explore_candidates`) 5~8개:** 블로그의 큰 줄기(`theme`) 안에서, 장부(`topics`)·무덤(`graveyard`)·탐색 후보(`explore_queue`)와
   같거나 비슷하지 않은 것. 실제로 사람들이 치는 한국어 검색어 1~5개를 붙인다(검색 수요는 파이프라인이 데이터랩으로 잰다).
   - invest: 이번 달·다음 달에 사람들이 찾는 돈·생활 질문 중 공식 숫자로 답할 수 있는 것.
   - tistory: 많이 검색되는 오류(정확한 오류 문구가 있는 것) 중 공식 문서로 해결을 확인할 수 있는 도구 계열.
   - guide: 이번 달·다음 달에 접수·기한이 돌아오는 시험·자격증, 계절 민원(이사철·방학 전 여권 등), 자주 찾는 생활 법 절차 중 시행기관 공고·법령 원문으로 확인할 수 있고 로그인 없이 열리는 공식 안내 화면이 있는 것.
   - guide의 글 꼬리표 `format`(steps 따라하기 / table 일정·기준표 / cases 상황별)과 `captures`·`photos`(실제 이미지 수)도 점수와 맞대어 본다. 실제 이미지를 생성 그림으로 바꾸자는 제안은 하지 않는다(이 블로그의 원칙).
4. 유망·주력 주제마다 통계 화면에서 찾은 **실제 유입 검색어**를 `topic_keywords`에 모은다(INPUT `topics`의 이름 그대로 키로).

## 4. 플레이북 새 판 (`learned_md`)

글쓰기 스킬이 매번 함께 읽는 짧은 문서(4,000자 이내)다. 아래 순서로 **전체를 새로** 쓴다(지난 판에서 여전히 맞는 것은 남긴다).

```
# <블로그> 플레이북 (TODAY 기준)
## 지금 상태
- 막힌 단계와 근거 1~3줄
## 통한 것 (근거 있는 것만, 글 수·점수 함께)
## 안 통한 것
## 다음 글에 적용할 것 (구체적으로: 제목 앞 검색어, 표 위치, 분량 등 — 스킬 규칙 범위 안에서)
## 리서치 메모 (TODAY)
- 상위 글 패턴, 플랫폼 변화(출처)
```

`## 확정 규칙 (블로그 주인 승인)` 부분은 쓰지 않는다(파이프라인이 그대로 붙인다).

## 5. 큰 변경 제안 (`proposals`, 0~3개)

플레이북만으로 안 되고 블로그 주인이 정해야 할 것: 글 구조를 바꾸는 규칙, 발행 시각, 카테고리, 새 실험 변수(예: 썸네일 문구 방식) 등.
각 제안은 글쓰기에 그대로 붙일 수 있는 **한 문장 규칙**과 근거(숫자)로 쓴다. 근거가 약하면 내지 않는다. 승인되면 플레이북의 확정 규칙이 된다.

## 6. 결과물 — `OUTPUT` (Write, UTF-8 JSON 하나)

```json
{
  "funnel": {"stage": "데이터 부족|채널|수요|노출|클릭|읽기", "evidence": "근거 숫자 1~2문장"},
  "patterns": ["꼬리표 × 점수에서 보인 패턴(가설이면 '가설:'로 시작)"],
  "topic_keywords": {"주제 이름": ["실제 유입 검색어", "..."]},
  "explore_candidates": [{"name": "주제 이름(2~6단어)", "keywords": ["검색어", "..."], "why": "왜 지금 이 주제인가"}],
  "research_notes": ["상위 글·플랫폼 변화 메모(출처 URL)"],
  "learned_md": "# ... 플레이북 전체",
  "proposals": [{"text": "한 문장 규칙", "evidence": "근거"}],
  "report": "블로그 주인에게 보낼 요약 3~5줄(무엇을 배웠고 다음 주에 무엇을 해 보는지)"
}
```

저장한 뒤 마지막 응답은 "막힌 단계 / 탐색 후보 N개 / 제안 N개" 한 줄.
