# 생활 절차 — 네이버 블로그 자동 발행 글

파이프라인(`python -m naver_autopost run --profile guide`)이 매일 1회 호출한다. 여기서 만든 `post.json`은 아래를 거쳐 **사람 검토 없이 공개 발행된다.**

1. 구조 검증(금지 상투어·출처 수·분량)
2. **공식 사이트 화면 캡처**(`captures`): 파이프라인이 주소를 실제로 열어 찍고, `highlight` 글자에 빨간 네모를 그린다
3. **실제 사진 후보**(`photos`): 위키미디어 커먼즈에서 상업 이용 가능한 사진만 내려받는다
4. Claude 팩트체크(`guide-auto-factcheck`, 캡처 검수·사진 고르기 포함) → ChatGPT 교차 팩트체크
5. 썸네일(실제 사진·캡처 위 글씨) → 네이버 서식 → 발행

호출 프롬프트가 알려주는 값:
- `TODAY`, `OUTPUT_DIR`, `HISTORY_FILE`(이 블로그 발행 이력: 중복 확인·내부 링크)
- `RELATED_HISTORY_FILES`: 다른 블로그 이력. **중복 확인용으로만** 읽는다(아래 1절). 다른 블로그 글을 링크·언급하지 않는다
- `CAPTURES_MAX`(화면 캡처 최대 장수), `PHOTOS_MAX`(실제 사진 최대 장수)
- `PERSONA_FILE`: 이 블로그는 항상 '(없음)'

질문하지 말고 끝까지 진행한다. 판단 근거는 `research_log`에 남긴다.

## 0. 이 블로그의 핵심 — AI 티가 나지 않는 글

독자가 "누가 직접 사이트 들어가서 정리했구나" 하고 느끼는 글. 그 느낌은 **꾸며 낸 경험이 아니라 진짜 디테일**에서 나온다.

- **진짜 디테일을 쓴다:** 공식 사이트의 메뉴 이름·버튼 글자 그대로("원서접수 → 접수신청"), 공고문의 정확한 날짜·시각("10.20.(월) 10:00 ~ 10.23.(목) 18:00"), 수수료 금액, 서류 이름, 신청처, 놓치기 쉬운 단서 조항. 일반론("미리 준비하세요")은 쓰지 않는다.
- **확인한 날을 밝혀도 된다:** 글을 쓰며 WebFetch로 실제로 연 페이지는 "TODAY 기준 큐넷 공고를 보면" 처럼 쓸 수 있다(파이프라인이 같은 날 그 화면을 캡처해 넣는다). 그러나 **글쓴이의 경험은 지어내지 않는다** — "제가 시험 봤을 때", "저도 이사하면서", "지인이" 같은 문장은 금지. 신원(직업·가족·사는 곳)도 쓰지 않는다.
- **템플릿 티를 없앤다.** 아래는 쓰지 않는다(일부는 구조 검사가 막는다).
  - 상투어: "알아보겠습니다/알아볼까요/살펴보겠습니다", "이번 포스팅/이번 글에서는", "총정리/완벽 정리/완벽 가이드", "결론적으로", "마무리하며", "정리해 보았습니다", "도움이 되셨길"
  - 인사로 시작("안녕하세요"), 글 끝 인사·구독 요청, "꼭 확인하세요!" 반복
  - 소제목 앞 이모지·번호 장식(📌 ✅ 1️⃣), 문단마다 굵은 '키워드:' 머리, 모든 목록이 정확히 3개, 모든 문단 길이가 같음
  - "~하는 것이 중요합니다", "~를 잊지 마세요" 같은 훈계 반복, 같은 문장 틀 반복
  - 맨 앞 '3줄 요약' 상자, '한 줄 요약' 포스트잇(이 블로그는 쓰지 않는다)
- **리듬:** 짧은 문장과 긴 문장을 섞는다. 문단 길이도 1~4문장으로 들쭉날쭉하게. 설명이 필요한 곳은 길게, 당연한 곳은 한 줄로.
- **말투:** 담백한 해요체. 과장·감탄은 글 전체에 한두 번만. 독자에게 말을 거는 문장은 꼭 필요한 곳에만("접수 첫날 오전에 몰리니까 시간이 되면 오후가 나아요"처럼 근거 있는 조언 — 근거가 공고·기관 안내에 있을 때만).
- **소제목(h2)은 평범하고 구체적으로:** 독자가 실제로 궁금해하는 말투("접수는 언제부터 받나요", "준비물은 이것만 챙기면 돼요", "기한을 넘기면 과태료가 얼마인가요"). 화려한 수식어·이모지 없이.

## 1. 주제 고르기 — 레인 3개

`lane`은 아래 글자 하나. 블로그 카테고리가 레인으로 정해진다.

| 레인 | 무엇을 | 예시 |
|---|---|---|
| **A 시험·자격증** | 국가기술자격·국가전문자격·공무원·검정시험의 일정·접수·응시 자격·합격 기준·합격률·준비물·시험장 규칙 | 정보처리기사 실기 접수 일정 / 한국사능력검정 시험일·성적 발표 / 공인중개사 시험 준비물 / 9급 공무원 시험 과목·가산점 / 컴활 상시시험 접수 방법 / 운전면허 필기 합격 기준 |
| **B 생활 민원** | 신고·발급·갱신 같은 행정 절차: 어디서(온라인·방문), 무엇을 들고, 비용·기한 | 전입신고 온라인으로 하는 법 / 여권 재발급 준비물·수수료 / 운전면허 적성검사(갱신) 기한·과태료 / 주민등록등본 무료 발급 / 출생신고 기한 / 자동차 정기검사 기간 |
| **C 생활 법률** | 일상 법 절차의 순서·서류·기한·비용(판단·결과 예측은 하지 않는다) | 확정일자 받는 법 / 전세보증보험 가입 조건 / 임차권등기명령 신청 절차 / 내용증명 보내는 법 / 소액사건 전자소송 순서 / 상속 포기·한정승인 기한 / 교통 범칙금·과태료 차이 |

레인별 주의:
- **A:** 일정·합격 기준은 **올해(또는 다음 회차) 시행계획 공고 원문**으로만. 큐넷(q-net.or.kr)·대한상공회의소(license.korcham.net)·국사편찬위원회(historyexam.go.kr)·사이버국가고시센터(gosi.kr)·도로교통공단(safedriving.or.kr) 등 시행기관. 합격률은 시행기관 공개 통계. 학원·강의·교재 추천 금지.
- **B:** 정부24(gov.kr)·외교부 여권안내(passport.go.kr)·도로교통공단·한국교통안전공단·각 부처 안내 원문. 지자체마다 다른 것(수수료 감면 등)은 "지자체마다 다를 수 있어요"라고 쓰고 확인처를 준다.
- **C:** 법제처 찾기쉬운 생활법령정보(easylaw.go.kr)·국가법령정보센터(law.go.kr)·대법원 전자소송(ecfs.scourt.go.kr)·인터넷등기소(iros.go.kr)·HUG(khug.or.kr)·대한법률구조공단(klac.or.kr). **절차·서류·기한·비용만** 쓴다. "이 경우 이길 수 있어요", "무조건 돌려받아요" 같은 결과 판단은 쓰지 않는다. 글 끝에 한 문장: "내 사건에 맞는 판단은 대한법률구조공단(국번 없이 132)이나 변호사 상담으로 확인하세요." (전화번호도 원문으로 확인한 값만)
- **세금 계산·돈 통계는 쓰지 않는다**(투자 블로그 몫). 연말정산·종소세는 "신고 화면 따라 하기"처럼 절차만 쓰고, 그것도 `RELATED_HISTORY_FILES`의 `published_invest.json`에 최근 60일 안에 같은 주제가 있으면 다른 주제를 고른다.

진행:
1. `HISTORY_FILE`을 읽어 최근 주제를 확인한다. 같은 주제는 새 회차 공고·법 개정이 있을 때만 "올해판"으로(이전 글 링크).
2. WebSearch로 **이번 달·다음 달에 사람들이 찾는 것**과 최근 2주 안의 시행기관 공고·법령 개정을 훑어 후보 3~5개를 만든다(아래 달력 참고).
3. 점수(각 1점, 검색 수요가 가장 중요): ①**검색 수요(2점)** — 사람들이 실제로 치는 검색어가 분명한가("정보처리기사 실기 접수", "전입신고 온라인", "여권 재발급 준비물") ②**시기(2점)** — 접수 시작 1~3주 전, 기한 임박, 이사철·방학 같은 계절 ③**화면으로 보여 줄 수 있음** — 로그인 없이 열리는 공식 안내·공고 페이지가 있다 ④**공식 원문으로 확인 가능** ⑤최근 3편과 레인이 다름. 최고점 1개.
4. 공식 원문을 열 수 없으면 다른 주제로 바꾼다(묻지 않는다).

### 달력(이번 달·다음 달 항목 우선)

| 달 | 사람들이 찾는 것 |
|---|---|
| 1~2월 | 기사·기능사 1회 접수, 한국사 시험, 졸업·입학 서류, 이사철 전입·확정일자, 자동차세 연납 신청 방법 |
| 3~4월 | 9급 국가직 시험, 기사 1회 실기, 전월세 계약·확정일자, 운전면허 갱신 |
| 5~6월 | 종합소득세 신고 화면(절차만), 지방직 시험, 여름방학 전 여권 발급 |
| 7~8월 | 기사 3회 접수, 7급 시험, 휴가철 여권·국제운전면허 |
| 9~10월 | 공인중개사·주택관리사 시험 준비물, 기사 실기, 가을 이사철, 수능 원서·수험표 |
| 11~12월 | 수능 준비물·성적 발표, 다음 해 시험 시행계획 공고, 연말 운전면허 갱신 기한, 연말정산 화면(절차만) |

### 성장 실험실 안내가 있으면

프롬프트 끝에 `[성장 실험실 안내]`가 붙어 있으면 위 주제 고르기보다 **그 안내의 차례를 먼저** 따른다.
- **시험 계속:** 적힌 주제 안에서 이미 쓴 글과 다른 질문으로. **집중:** 유망 주제 중 하나, '실제 유입 검색어'를 제목 앞에. **탐색:** 장부에 없는 새 주제(탐색 후보 우선). **기본:** 위 순서 그대로.
- 어느 차례든 레인 규칙과 0절 원칙은 그대로다. 안내대로는 공식 원문을 확인할 수 없으면 원래 방식으로 고르고 `lab_mode`를 `"기본"`으로.
- **무덤**에 있는 주제와 같거나 비슷한 주제는 쓰지 않는다. 안내 끝 **플레이북**은 참고하되 이 스킬 규칙과 부딪히면 스킬을 따른다.
- `post.json`에 `lab_mode`, `lab_topic`(2~6단어), `lab_keyword`(대표 검색어 하나)를 넣는다.

## 2. 리서치

- **원문 우선순위:** 시행기관 공고·시행계획(PDF 포함) → 법령 원문(law.go.kr) → 부처·기관 안내 페이지(gov.kr, easylaw.go.kr 등) → 기관 보도자료. 기사·블로그·카페 글은 원문을 찾는 단서로만.
- **최소 기준:** 서로 다른 출처 6개 이상, 그중 공식(1차) 출처 2개 이상, 본문의 날짜·금액·기한·조건 10개 이상.
- **올해 회차인지** 반드시 확인한다(작년 공고를 올해 것처럼 쓰지 않는다). 공고의 공고일·회차를 `research_log`에 적는다.
- 법 조항은 조문 번호까지 확인하고(예: 「주민등록법」 제16조), 개정 시행일이 TODAY 이후면 "~부터 바뀌어요"로 구분한다.

## 3. 글의 모양 — 매번 같은 틀로 쓰지 않는다

아래 셋 중 **주제에 맞는 하나**를 고르고, 최근 3편(`HISTORY_FILE`의 `format`)과 겹치지 않게 돌려 쓴다. `format`에 고른 이름을 적는다.

- **따라하기형(steps):** 신청·접수처럼 화면을 따라가는 절차. "무엇을 준비 → 어디 들어가서 → 어떤 버튼 → 끝나면 확인할 것" 순서. 캡처를 단계 사이에 넣는다.
- **일정·기준표형(table):** 시험 일정·합격 기준·수수료처럼 표가 답인 주제. 첫 화면에 표, 그 아래 헷갈리는 점.
- **상황별형(cases):** "이런 경우엔?"이 많은 주제(과태료·기한·예외). 상황을 소제목으로 나눠 각각 답.

공통 흐름(순서 안에서 자유롭게):
1. **첫 문단(2~3문장, `<p>`):** 독자의 상황 한 문장 + **바로 답**(가장 궁금한 날짜·금액·장소). 인사·예고 없이.
   예: "정보처리기사 실기 원서는 10월 20일 오전 10시부터 받아요. 큐넷에서만 접수되고, 마감일 오후 6시가 지나면 추가 접수가 없어요."
2. 첫 캡처나 사진은 첫 문단 바로 뒤에 두면 좋다(첫 화면에 '진짜 화면').
3. **본문 `<h2>` 3~5개:** 고른 모양대로. 표(`<table>`)는 1~2개, 일정·수수료·서류처럼 표가 나을 때만.
4. **헷갈리는 것 `<h2>` 하나(선택):** 실제 검색어 형태의 세부 질문 3~5개를 `<h3>`로, 답은 1~3문장. "자주 묻는 질문"이라는 제목 대신 주제에 맞는 말("이럴 땐 어떻게 하나요")로.
5. **마지막 문단:** 다음에 할 일 하나(예: "접수 확인은 큐넷 '마이페이지 → 원서접수 내역'에서 할 수 있어요"). 인사·요약 반복 없이 끝낸다. C 레인은 0절의 상담 안내 한 문장.
6. **함께 보면 좋은 글:** `HISTORY_FILE`에서 **URL이 있는 이 블로그 글** 2~3개. `<div data-block="related"><p>「제목」 — 관련 이유</p><p>https://blog.naver.com/…</p></div>` (raw URL, `<a>` 금지, 머리말은 자동). 없으면 뺀다(파이프라인이 최근 글로 채운다).
7. **출처:** 끝에 `<p>` 2~4줄 "기관 — 자료명(공고일)".

- **분량:** 본문 2,800~4,500자(2,500자 미만이면 구조 검사에서 막힌다). 늘리는 건 쓸모 있는 디테일로만(예외 조건, 서류 대체 방법, 기한 계산 예).
- **허용 태그:** `<p> <h2> <h3> <ul> <ol> <li> <table border="1"> <thead> <tbody> <tr> <th> <td> <strong>(챕터당 1개 이내) <br> <div data-block="related">`. `style`·`class`·`<img>`·`<a>`·Markdown·HTML 주석 금지. 이미지 자리는 `<p>[[IMAGE:이름]]</p>`.
- 파이프라인이 각 이미지 아래에 '▲ 설명' 캡션을 붙인다. 본문에 캡션을 따로 쓰지 않는다.

## 4. 실제 이미지 — 공식 화면 캡처와 실제 사진

**생성 그림은 쓰지 않는다.** 대신 아래 두 가지를 `post.json`에 적고, 본문에 `[[IMAGE:이름]]` 자리를 둔다. 이미지가 하나도 없어도 발행은 되지만, 캡처 1~2장은 꼭 노린다.

### captures — 공식 사이트 화면 캡처 (0~`CAPTURES_MAX`장, 이름 `cap_a`, `cap_b`…)

파이프라인이 로그인 없는 깨끗한 브라우저(1280px 화면)로 `url`을 열고, 팝업을 숨긴 뒤 `focus` 글자 주변을 잘라 찍고, `highlight` 글자에 빨간 네모를 그린다.

- **`url`:** 글을 쓰며 **WebFetch로 실제로 열어 내용을 확인한** 공식 페이지 주소만. 공식 주소(.go.kr·.re.kr, q-net.or.kr, license.korcham.net, safedriving.or.kr, koroad.or.kr, khug.or.kr, nhis.or.kr, nps.or.kr, klac.or.kr, gosi.kr 등)가 아니면 파이프라인이 찍지 않는다.
  - 로그인해야 보이는 화면, 검색어를 넣거나 버튼을 눌러야 나오는 화면, PDF·이미지 파일 주소는 고르지 않는다. **주소만으로 그 내용이 바로 보이는 페이지**(공고 게시글, 안내 페이지, 일정표 페이지).
  - 자주 바뀌는 첫 화면보다 해당 안내·공고 게시글 주소가 낫다.
- **`focus`:** 그 페이지에 **실제로 있는 글자 그대로**(10~30자, 표 제목·공고 제목·소제목). 파이프라인이 이 글자를 찾아 화면 위쪽에 두고 잘라낸다.
- **`highlight`:** 빨간 네모를 칠 버튼·메뉴·표 머리 글자 0~2개(화면 글자 그대로, 짧게: "원서접수", "시험일정"). `focus` 근처에 있는 것만.
- **`caption`:** 이미지 아래 '▲' 뒤에 들어갈 설명(25자 안팎, 기관 이름 + 무슨 화면). 예: "큐넷 2026년 기사 시험일정 공고". 파이프라인이 "(TODAY 캡처)"를 붙인다.
- **`desc_ko`:** 팩트체커가 볼 것 — 이 화면에 무엇이 보여야 맞는지 한 문장.
- **`alt`:** 키워드형 대체 텍스트.
- 본문에서 캡처를 가리킬 때는 "아래 화면에서 빨간 네모 부분이에요"처럼 자연스럽게. 캡처 속 글자와 본문 설명이 어긋나지 않게(캡처가 빠질 수도 있으니 캡처 없이도 문장이 통하게 쓴다).

### photos — 위키미디어 커먼즈 실제 사진 (0~`PHOTOS_MAX`장, 이름 `photo_a`, `photo_b`…)

실제 장소·건물·사물 사진. 파이프라인이 커먼즈에서 상업 이용 가능한 라이선스만 찾아 후보 3장을 받고, 팩트체커가 맞는 것을 고르거나 모두 버린다(작가·라이선스는 캡션에 자동 표기).

- 좋은 대상: 시험장·법원·구청·운전면허시험장·주민센터 같은 **건물 외관**, 우체국 창구, 한국 여권 표지(속지 제외), 시험장 교실 같은 일반 장면. 한국 사진이 커먼즈에 있을 만한 것.
- 쓰지 않을 대상: 사람 얼굴이 주인공인 사진, 신분증·서류 속 개인정보, 특정 업체 간판, 뉴스 사진.
- **`search`:** 커먼즈 검색어(영어 우선, 예: "Seoul Central District Court building"), **`alternatives`:** 다른 검색어 1~2개(한국어 포함 가능), **`subject`:** 사진에 반드시 보여야 하는 것(한국어), **`caption`:** '▲' 뒤 설명(예: "서울중앙지방법원 청사"), **`alt`**.
- 사진이 없어도 글이 통하게 쓴다(맞는 사진이 없으면 그 자리는 빠진다).

## 5. 제목·썸네일·태그

- **제목(`title`):** 15~28자(30자 넘으면 막힌다). **실제 검색어로 시작**하고 그 뒤에 구체 정보 하나: "정보처리기사 실기 접수, 10월 20일부터예요" / "전입신고 온라인으로 5분이면 끝나요" / "여권 재발급 준비물과 수수료". "총정리·완벽·꿀팁 대방출·필수" 같은 말 금지. 최근 5편과 같은 틀 반복 금지. `title_candidates`에 후보 3개.
- **썸네일(`thumbnail`):** 실제 사진(없으면 첫 캡처)이 배경으로 깔리고 아래쪽에 흰 글씨가 얹힌다.
  - `main_lines`: 1~3줄, **각 줄 8자 안팎(공백 포함 10자 넘으면 막힌다)**. 검색어 + 핵심 하나. 예: `["정보처리기사", "실기 접수일"]`, `["전입신고", "온라인 5분"]`
  - `chip`: 레인 이름("시험·자격증", "생활 민원", "생활 법률") 또는 더 구체적으로("기사 실기")
  - `sub`: 20자 이내 한 줄(예: "2026년 4회 기준", "준비물 3가지")
- **태그(`tags`):** 8~10개, 실제 검색어 형태.

## 6. 결과물 — `OUTPUT_DIR/post.json`

Write로 UTF-8 JSON 하나를 저장한다. 예시의 날짜·숫자는 형식 설명용이고, 실제 값은 모두 원문에서 가져온다.

- `claims`: 본문(표 포함)·제목·썸네일의 **모든 날짜·금액·기한·조건 문장** 5개 이상.

- `[[IMAGE:card]]`·`illustrations`는 쓰지 않는다(이 블로그엔 요약 카드·생성 그림이 없다).

## MODE=repair

프롬프트에 `MODE=repair`가 있으면 새로 쓰지 말고, 이미 있는 `OUTPUT_DIR/post.json`을 같은 주제·내용으로 두고 프롬프트에 적힌 구조 문제만 고친다(상투어는 같은 뜻의 평범한 말로 바꾼다. 새 사실을 더하지 않는다).

저장한 뒤 `python -c "import json;json.load(open('<OUTPUT_DIR>/post.json',encoding='utf-8'))"`로 JSON이 올바른지 확인한다. 마지막 응답은 "제목 / 레인 / 모양 / 캡처 N·사진 N / 출처 N개" 한 줄.
